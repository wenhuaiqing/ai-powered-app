# ai-powered-app

Mock of Reapit's "One Platform" — a portfolio demo built around Sydney house-price Kaggle data. Showcases multi-agent AI (LangGraph), RAG (NSW regulations), text-to-DuckDB, live web search (Tavily), and a RandomForest valuation model. Frontend mirrors Reapit's indigo/teal visual identity. Deployed on Azure Container Apps — see the root README for the live topology.

The plan of record lives at `~/.claude/plans/under-misc-folder-each-quiet-starfish.md` (outside this repo). Read it before making structural changes.

## Tech stack

- **Backend**: FastAPI 0.111+, Python 3.12, uv. MySQL for OLTP (SQLAlchemy + PyMySQL), DuckDB for analytics, rebuilt from MySQL by `scripts/etl_mysql_to_duckdb.py`. LangGraph + `openai` SDK. scikit-learn for ML. Tavily for web search. Local cosine over parquet for RAG.
- **Frontend**: React 18.3, Vite 5, React Router 7, Recharts, Leaflet, `react-ai-orb`, lucide-react.
- **AI**: chat and embeddings sit on **separate endpoints**, both spoken over the OpenAI protocol. Chat runs on Gemini (`gemini-3.5-flash-lite` via `https://generativelanguage.googleapis.com/v1beta/openai/`); embeddings stay on Azure OpenAI (`text-embedding-3-small`, 1536-D, over the GA deployments endpoint — the `/openai/v1` surface 404s embeddings), because swapping the embedding model means rebuilding the RAG parquets so corpus and query vectors match. Stay on a Lite chat model: `gemini-3.5-flash` is capped at 5 requests/minute and one Orb run is 5-9 sequential calls, which degrades silently to keyword routing. `LLM_BASE_URL`/`LLM_API_KEY` drive chat; `EMBED_BASE_URL`/`EMBED_API_KEY` drive embeddings and fall back to the `LLM_*` pair when unset. Provider is a settings flag — `services/llm.py` + `services/embed.py` dispatch on `LLM_PROVIDER` / `EMBED_PROVIDER`; the earlier AWS Bedrock path (Claude Sonnet 4.6 + Titan Embed v2) is retained behind `bedrock` as reference. Switching embed providers means rebuilding the RAG parquets — the vector widths differ.

## How to run

```powershell
# 0) MySQL (OLTP source of truth)
docker compose up -d mysql

# 1) Build data + model (one-time, regenerate after CSV changes)
cd backend
uv sync
uv run python ../scripts/seed_all.py     # migrate + build MySQL + ETL to DuckDB
uv run python ../scripts/train_model.py
uv run python ../scripts/build_review_embeddings.py
uv run python ../scripts/build_regulation_corpus.py
# (scripts/build_db.py is the legacy DuckDB-only path, no MySQL)

# 2) Backend
uv run uvicorn src.main:app --reload --port 8000

# 3) Frontend (separate terminal)
cd frontend
npm install
npm run dev   # :5173
```

Tests: `cd backend && uv run pytest`.

## Conventions

- **No emojis in code or output unless asked.**
- **Australian English** throughout (colour, organise, metre). Dates DD/MM/YYYY where displayed.
- Thin routers — handler ≤20 lines; SQL + business logic in `services/`.
- Every agent emits a Pydantic-typed JSON object (structured outputs). Never free text into graph state.
- LangGraph is the harness — per-node 30s timeout, 90s end-to-end, 1 retry on validation errors.
- The Orb is the primary user surface — streamed SSE events render as agent-trace cards.
